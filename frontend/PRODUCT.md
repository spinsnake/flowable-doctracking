# Product context

MFU Document Tracking is a web application for university staff, unit administrators, central administrators, and explicitly assigned couriers. It records a document's immutable route and tracking model, shows scoped history and evidence, and coordinates workflow through the backend.

Confirmed requirements: Thai UI, Google-only login using allowlisted @mfu.ac.th accounts, role and Unit scope, login email notification, versioned route templates, document title or number, private validated photo evidence, single-document reservation and cancellation. P3 exposes the Model B flow: origin READY, single courier reservation, physical pickup with validated photo, own active legs and drop-off with photo, unit receipt and READY, and origin return confirmation. Unit worklists and courier eligible pickup queues remain separate; courier queries expose only scoped route and custody references. P4 exposes Model A physical pickup and photo drop-off without unit READY/receipt, with COURIER_TRACKING_COMPLETE distinct from Model B completion. Central admins can change the audited default for newly created documents only. Couriers can record scoped physical observations; noncurrent/offroute observations record an unknown transfer gap and hold workflow as an exception pending P5 resolution. Registry and Station lists filter loaded rows by model/business state. Bulk transport and exception resolution belong to later phases. Accepted workflow commands remain read-only while synchronization is pending; the UI polls operation status without repeating the mutation. Display no fabricated business records or metrics.

## Platform
Web: Nuxt 4 SPA, Vue 3, TypeScript, Nuxt UI 4, Tailwind 4. Same-origin /api/v1 backend; no browser OAuth tokens or application passwords. Mobile web remains the same product and visual system.
